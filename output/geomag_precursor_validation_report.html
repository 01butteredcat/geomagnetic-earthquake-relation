教授建議方法驗證：surrogate 檢定・多事件疊加・z 規則回測

對具向量磁力資料組別的 Pc3/Pc4 近遠站極化差分序列（pc3_diff_zh / pc4_diff_zh）進行的方法論檢驗

這份報告在回答什麼問題： 先前報告指出 G10（2024/4/3 花蓮 M7.2）震前 4 天（2024-03-30）的 Pc3 近遠站極化差分，是整個 113 天窗口中最極端的一天（z ≈ -4.1 個 MAD 單位），但也自陳「z=4 很罕見」的常態直覺並不嚴謹適用、且未做多重比較校正。 這份報告針對這個缺口做三件事：(1) 不假設常態分布，改用 block bootstrap／相位隨機化把序列洗牌成「統計長相一樣但跟地震無關」的代理序列，看多常會自己冒出這麼極端的下沉（2026-09-25 更正：這兩種整條序列的做法後來證實都不能下結論，現行主要結果改為第 1 節開頭的震前窗口排名檢定）； (2) 把「一次地震」擴充成這幾年測網附近所有 M≥5.5 的獨立地震（去叢集後 23 起，另附 M≥6.0／強震子集與 M≥5.0／全集當敏感度對照，見下方三層切換），把各組序列依發震時刻對齊疊加，看 3/30 那種下沉疊完會不會浮現； (3) 把 z ≤ -4.1 這條規則當成一條真正的警報規則，回測它在整個資料集上的命中與誤報表現。 仍然缺乏獨立的「安靜期」對照資料，去叢集規則是簡化版，見文末「方法限制」。

總覽

1. Surrogate 檢定：這種下沉在「跟地震無關」的資料裡多常見？

2026-09-25 更正：本節下方的整條序列檢定不能當證據。 block bootstrap 的代理序列由觀測序列自己的區塊重組，被檢定的極值會被抽進自己的虛無分布，所以 p 值有結構性下限：在本專案 100–300 天的序列長度下，就算注入 100 倍標準差的尖峰，p 值仍在 0.2–0.4。它的「不顯著」不代表下沉常見。 相位隨機化則會把重尾抹平，偏向寬鬆。兩者的結論相反，但都不可信。 現行的主要檢定是下方的震前窗口排名檢定：把序列切成對齊真窗口、互不重疊的 30 天區塊，看震前窗口的最低值在所有區塊中排第幾，p = 名次 ÷ 區塊數；跨組以 Fisher 法合併，虛無分布由「每組隨機挑一個區塊當真窗口」模擬。 中間曾用過的「留一窗 block bootstrap＋安慰劑校準」版本（Pc3 6/12 組、p=0.006）也已撤回：它只能重組背景期已有的數值，窗口最小值只要低於背景最小值，p 就固定在下限 0.0005。 細節見 data/interim/surrogate_test/window_summary.md 與 docs/statistical_methods.md。

常態性檢定（Shapiro-Wilk）先確認不能假設常態；接著用 block bootstrap（保留短期自相關、打亂時間位置）與 FFT 相位隨機化（保留頻譜結構、隨機化相位）各產生 2000 組代理序列，重算同一套 median/MAD z-score 公式的 min(z)，得到虛無分布

各組 × 2 頻段明細（舊版整條序列檢定）

p(≤觀測極值)：代理序列的 min(z) 比該組實際觀測到的還極端的比例。p(≤-4.1)：代理序列中出現任一天 z≤-4.1 的比例（直接回答「這個規則在無關資料裡多常自己冒出來」）。反白列＝block bootstrap 與相位隨機化兩種方法的 p(≤-4.1) 皆低於 0.05。block bootstrap 欄有結構性下限、相位隨機化欄偏寬鬆，兩欄都不能用來判斷顯著與否（見本節開頭的更正）。

方法限制

  • 仍缺獨立的「安靜期」對照資料：null band／surrogate 都是從既有 13 組的資料窗口內部構造出來的（隨機假發震日、洗牌既有序列），不是額外抓取的、確定跟任何地震無關的長期背景資料——這是專案文件裡一直標記為「完全缺少」的部分，本次修改沒有解決它，只是在現有資料內盡量逼近。
  • 去叢集規則是簡化版：同一序列的餘震只用「3 天內、100km 內、規模較小」剔除，不是正式的 ETAS 或 Reasenberg 去叢集演算法；且即使去叢集後，仍有事件的疊加視窗（-30~+10 天）彼此重疊（例如同組內兩起獨立地震相隔僅 20 天），疊加樣本嚴格來說不是完全獨立的。
  • Near/far 站別分類每組只算一次（依錨定事件距離），套用到同組內其他事件時沿用同一分類，沒有針對每個候選地震的實際震央重新計算——同組內震央通常相近，此簡化影響應該不大，但未驗證。
  • 整條序列的 block bootstrap 與相位隨機化都不能下結論（2026-09-25 更正）：兩者在多數組別給出相反的結論（block bootstrap 通常不顯著、相位隨機化通常顯著），但原因不是「重尾分布下極端值本來就常見」。block bootstrap 的代理序列由觀測序列自己的區塊重組，被檢定的極值會混進自己的虛無分布，p 值有結構性下限（注入 100σ 尖峰仍約 0.2–0.4），所以它的不顯著沒有資訊；相位隨機化的代理序列邊際分布趨近常態、尾部變薄，偏向寬鬆。已改用震前窗口的不重疊區塊排名檢定（第 1 節開頭）。它的代價是短序列只切得出 3–11 塊，單組 p 最小只能到約 0.1–0.3，證據只能來自跨組合併。
  • M≥5.5 的 23 起事件雖達到專案文件提到的「20-30 起」統計門檻，但這只是達到樣本數量下限，不等於每起事件都有足夠資料品質／獨立性；G11 起 ttn 站缺測、部分組別震央座標信心較低（見 events.py 的 coord_confidence）等既有資料限制仍然適用。
  • M≥6.0 那一欄樣本數通常很小（常見個位數）：樣本數過小時，binomial 檢定／empirical p 值有下限（即使全部命中，p 值也無法無限逼近 0），此時「不顯著」不代表訊號不存在，只代表這個規模門檻下的檢定力本身受限——這正是三層對照而非單一門檻的原因：M≥6.0 犧牲樣本數換取較強的單一事件訊噪比，M≥5.0 犧牲訊噪比換取樣本數，兩者互為印證而非互斥。
  • 本報告的地震目錄：G11/G12/G13/G20（2024-09~2026-07 的窗口）採用使用者提供的 CWA GDMS 規模報告匯出（GDMScatalog.txt）；其餘組別仍用 USGS FDSN 公開目錄 API（即時查詢）。各筆事件的實際來源見「疊加使用的事件清單」/回測表格的「來源」欄。
