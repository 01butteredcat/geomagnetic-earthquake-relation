## 備註

- **G10 需要延伸現有範圍**：現有 `geomag_precursor_report.html` 只抓到 2024-01-01~2024-04-25，未涵蓋 05-10 的 M6.0 餘震，04-23 的兩筆餘震也僅勉強在範圍邊緣。若要把 G10 納入多事件統計，建議把既有 pipeline 的資料範圍延伸到 2024-06-01。
- **G11（嘉義大埔）是唯一內陸、非隱沒帶相關的事件**：其餘 12 組都集中在宜蘭-花蓮外海的隱沒帶/板塊邊界構造，大埔地震屬於內陸碰撞帶斷層，構造背景不同，統計上是否該與其他組一起檢定需另外考慮（可能需分層分析，或當作獨立子群）。
- 13 組獨立序列仍未達正式統計檢定建議的 20–30 起門檻（見 `/home/yuchi/.claude/plans/1999-9-21-2010-3-4-2015-2-14-2016-2-6-2-adaptive-tulip.md` 第1節），但已是有意義的擴充。
- 各組事件精確震央座標/深度/規模（CWA 為主、部分事件因查無 CWA 公開座標改用 USGS 交叉核對並標記信心）已整理於 `scripts/events.py`，供多組分析 pipeline 直接讀取；本表僅列區域名稱與規模，不重複列座標。

## 如何執行 13 組分析與跨組統計

Pipeline 已從單一事件（G10）泛化到可對任一組執行：

```bash
cd scripts
./run_pipeline.sh --group G10          # 單組：跑到 verify_pipeline.py 為止
./run_pipeline.sh --group G10 --full-report  # 單組 + 產出完整敘述性 HTML 報告（目前僅 G10 的敘述文字有意義）
./run_all_groups.sh                     # 全部 13 組（依 group_id 資料夾，10 個 group_id 對應 13 起事件），單組驗證失敗不中止整批
../.venv/bin/python3 cross_group_analysis.py  # 需先跑完 run_all_groups.sh；輸出 data/interim/cross_group_summary.{json,md}
```

各組實際可跑的方法（H/Z 向量篩選、ULF 極化、或僅 F 純量篩選）取決於該組向量站/純量站的實際站數（見 `common.py` 的 `MIN_STATIONS_FOR_METHOD` 門檻），`data/interim/all_groups_run_summary.json` 記錄每組實跑結果。G1 全組僅純量站、G2_G3 向量站僅 2 個不足門檻，因此這兩組只跑 F 法；G4 起向量站數足夠可跑 H/Z（+ULF）。
